## Plan — Judge sessions become first-class chats (v0.0.2)

**Core idea**: a Judge session = one `ConversationEntity(kind="JUDGE")` + JSON-carrying `MessageEntity` rows in the existing Room DB. No schema change, no migration — and because the Chats tab, Home Recent, search SQL, and backup export/import all read conversations/messages without kind filters, **listing, recents, search, export and import come for free**.

### 1. Storage model (JudgeViewModel.kt + data)
- First question creates the conversation: `kind="JUDGE"`, title = question truncated (~48 chars), `voice=false` automatically.
- One `role="system"` message holds the panel: `{"seats":[{connectionId,model}×3],"judgeSeat":N}`.
- Each turn = one `role="judge"` message whose `text` is the full Turn JSON (question, sentAt, phase, per-seat answers/reviews/consensus with text+error+latencyMs, failure). Turn gets a `messageId`; every `updateLast` phase change re-writes that row, so a crash mid-deliberation still leaves a resumable partial turn.
- `retryLast()` deletes the last turn row; follow-ups append rows; `touchConversation` keeps previews/timestamps fresh.

### 2. New judge chat from Home (your item 2)
- Home "Judge Mode" card → `AppViewModel.startJudgeChat()`: navigates to the judge screen with a **fresh** session (empty panel pre-filled from last-used seats for convenience).
- `JudgeViewModel` gains `newSession()` and `resume(conversationId)` (loads panel + turns from Room, mirroring `VoiceViewModel.resume`).

### 3. Open saved judge chats (your item 1)
- `AppViewModel.openConversation(id)`: add a `kind=="JUDGE"` branch → new `_pendingJudge` flow (same pattern as `_pendingVoice`) + navigate to the judge screen, which resumes that conversation.
- `ChatListRow` (ui/Shared.kt): judge conversations get the scale icon + accent tint instead of chat-bubble/mic.
- Search: add a "Judge" filter chip next to All/Voice/Starred (`runSearch` branch on `kind`).

### 4. Export / import (your item 3)
- Works with **zero backup-format changes**: `exportJson` dumps all conversations + message `role/text/createdAt`, and `kind` round-trips on import — judge rows included. Verified against the import guards (title/messages checks pass for judge rows). Vault, Downloads fallback, and daily auto-backup all inherit it.

### 5. Ship
- `versionName 0.0.2` / `versionCode 2`; commit → push `judge-panel` → trigger signed release → watch → fix loop until green → download `Aster-v0.0.2-release-signed.apk` to `Desktop\aster-apk\`.

**Behavior notes**: judge chats are read-only outside the judge screen (tapping one always opens Judge Mode, never ChatScreen); deleting/pinning/archiving a judge chat works like any chat; old in-memory sessions from v0.0.1 can't be recovered (nothing was ever stored).
